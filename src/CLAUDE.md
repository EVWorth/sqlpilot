# Frontend conventions (`src/`)

Applies to everything under `src/`. Project-wide rules are in `AGENTS.md`.

## Layout

| Path                 | What lives there                                                      |
| -------------------- | --------------------------------------------------------------------- |
| `components/<area>/` | React components by feature (editor, grid, schema, admin, agent, ...) |
| `stores/`            | Zustand stores; they own async work, loading and error state          |
| `lib/tauri-api.ts`   | the `api` object: policy over the generated bindings                  |
| `lib/bindings.ts`    | generated by `just bindings` from Rust; never edit                    |
| `lib/`               | pure helpers (SQL parsing, grid logic, formatting), each unit-tested  |
| `types/index.ts`     | hand-written shared types; snake_case to match Rust serde             |
| `hooks/`             | React hooks                                                           |
| `dev/mock/`          | mock backend for `?mock` (see the `ui-preview` skill)                 |

## Rules

- Components call store actions, never `api.*`. A store action sets
  `loading`/`error` itself; components read them.
- Import app code relatively (`../lib/tauri-api`). The `@/` alias works only in
  tests.
- Types mirror Rust: snake_case fields, ISO strings for timestamps (not
  `Date`). Prefer the generated types in `lib/bindings.ts` over restating them.
- No `any` and no `!` non-null assertions; narrow with a guard. If `any` is
  unavoidable, add an eslint-disable comment saying why.
- Conditional classes go through `clsx` and `twMerge`.
- Keep components under about 300 lines; split when they grow.
- Accessibility: buttons have labels, inputs have associated labels, focus is
  visible.
- No `console.log` left in app code.

## Store template

```ts
import { create } from "zustand";
import { api } from "../lib/tauri-api";
import type { Thing } from "../types";

interface ThingState {
  thing: Thing | null;
  loading: boolean;
  error: string | null;
  load: (id: string) => Promise<void>;
}

export const useThingStore = create<ThingState>((set) => ({
  thing: null,
  loading: false,
  error: null,
  load: async (id) => {
    set({ loading: true, error: null });
    try {
      set({ thing: await api.getThing(id), loading: false });
    } catch (e) {
      set({ error: String(e), loading: false });
    }
  },
}));
```

## Tests

- `__tests__/<Name>.test.tsx` next to the code: Vitest, jsdom and React
  Testing Library. Cover the error and loading states, not only the happy
  path.
- `*.browser.test.tsx` runs in real Chromium (`npm run test:browser`). Use it
  for layout, focus and anything jsdom fakes (measurements, Monaco).
- `vi.mock` paths must resolve; `scripts/check-test-mocks.sh` checks them in
  CI.
